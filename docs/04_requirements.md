# Формализация требований

приложение macOS для локальной стенограммы встреч и доказательного ИИ-ассистирования интервью. **Главный HR-процесс:** подготовка заключения рекрутера о кандидате после интервью, итоговое решение — только за человеком. Обозначения P1–P5 — проблемы AS-IS; H0–H4 — точки контроля TO-BE

## User Stories

### US-01. Подготовка вакансии и критериев

Как рекрутер, я хочу вставить описание вакансии и отредактировать извлечённые критерии, чтобы оценивать сказанное кандидатом только относительно согласованных требований.

Критерии приёмки:

```gherkin
Given выбран режим «Рекрутер», When пользователь вставляет текст вакансии и сохраняет его, Then система показывает редактируемые обязательные и желательные критерии с указанием происхождения из вакансии.
Given текст вакансии пуст, When пользователь пытается начать HR-аналитику, Then система требует указать вакансию и не создаёт несуществующие критерии.
Given модель предложила критерий, отсутствующий в вакансии, When рекрутер отклоняет его, Then критерий исключается из анализа, а исправление сохраняется в журнале.
```

Зависимости: локальное хранилище, парсер вакансии, H2. Риск: R4 (галлюцинация), R1 (справедливость).

### US-02. Законная запись кроссплатформенного ВКС

Как рекрутер, я хочу записывать доступный системный звук Zoom/Телемоста/TrueConf и собственный микрофон независимо от API платформы, чтобы сохранить полный источник интервью.

Критерии приёмки:

```gherkin
Given macOS предоставила необходимые разрешения и доступный аудиоисточник, When рекрутер начинает встречу, Then создаётся воспроизводимая локальная запись с тайм-кодами и видимым индикатором записи.
Given необходимого разрешения или допуска на запись нет, When пользователь нажимает «Начать запись», Then запись не запускается, причина показывается, доступен ручной режим.
Given во время записи отключён микрофон, When устройство пропадает, Then система фиксирует ошибку, сохраняет ранее записанное и явно сообщает о неполном источнике.
```

Зависимости: Audio Capture, H0. Риск: R14, R9.

### US-03. Локальная транскрибация и словарь терминов

Как рекрутер, я хочу получать потоковую стенограмму русскоязычного интервью с английскими и корпоративными терминами, чтобы не тратить внимание на ручное конспектирование.

Критерии приёмки:

```gherkin
Given установлена многоязычная локальная модель ASR, When во время встречи поступает русская речь, Then появляются предварительные и затем устойчивые сегменты со временем начала и окончания, без отправки аудио во внешний сервис.
Given в пользовательском словаре есть «RAG», «CI/CD», «СУДИР», When пользователь добавляет вариант написания, Then исправление может быть предложено без слепой замены неоднозначных слов; исходная версия доступна.
Given модель ASR не установлена, When начинается подготовка записи, Then система показывает отсутствие модели, предлагает установку или ручной режим без фиктивной стенограммы.
```

Зависимости: T3–T5, H1. Риск: R5.

### US-04. Определение и исправление говорящих

Как рекрутер, я хочу привязывать голоса к участникам и исправлять ошибки диаризации, чтобы слова интервьюера не приписывались кандидату.

Критерии приёмки:

```gherkin
Given имеются согласованные голосовые образцы участников, When приложение обрабатывает аудио, Then реплики получают speaker ID и, если есть надёжное сопоставление, имя участника.
Given модель не уверена или два человека говорят одновременно, When формируется реплика, Then показывается «неизвестный говорящий» или «требует проверки», а не придуманное имя.
Given рекрутер изменил говорящего у сегмента, When выполняется перерасчёт аналитики, Then связанные выводы становятся требующими повторной проверки, история изменения сохраняется.
```

Зависимости: T4, H1. Риск: R6.

### US-05. Доказательная трёхколоночная HR-таблица

Как рекрутер, я хочу автоматически получать и уточнять таблицу «преимущества / недостатки / особенности», чтобы быстро готовить проверяемое заключение.

Критерии приёмки:

```gherkin
Given критерии вакансии утверждены и есть подтверждённые реплики кандидата, When разрешённая LLM формирует ответ, Then система показывает три колонки, статус каждого вывода, тайм-код и source_segment_id.
Given кандидат не упоминал требуемый навык, When LLM формирует заключение, Then статус навыка «не выяснено», а не «отсутствует» или «недостаток».
Given LLM вернула ссылку на несуществующий сегмент, When валидатор разбирает ответ, Then вывод не публикуется как подтверждённый, ошибка протоколируется.
```

Зависимости: T7–T9, H2. Риск: R1, R4.

### US-06. Подтверждение выводов и человеческое кадровое решение

Как рекрутер и нанимающий руководитель, мы хотим проверять, редактировать и отклонять выводы ИИ, чтобы ответственность и окончательное решение оставались у людей.

Критерии приёмки:

```gherkin
Given сводка создана ИИ, When рекрутер не подтвердил её, Then статус остаётся «черновик», а автоматическая передача окончательной оценки руководителю блокируется.
Given рекрутер отклонил спорный вывод, When введена причина, Then исходный вывод, новая версия, автор и время фиксируются в review_log.
Given модель пометила кандидата как неподходящего, When нет кадрового решения уполномоченного человека, Then система не создаёт отказ, не меняет статус кандидата и не отправляет сообщение от имени работодателя.
```

Зависимости: H2, H3, decision_log. Риск: R1–R4.

### US-07. Аналитика в реальном времени и управление панелью

Как участник встречи, я хочу видеть обновляемые тезисы сбоку и скрывать панель, чтобы она не мешала разговору и при необходимости была доступна.

Критерии приёмки:

```gherkin
Given запись идёт и накопились новые стабильные сегменты, When разрешённый LLM API отвечает, Then панель обновляет черновик сводки и показывает время последнего анализа.
Given панель открыта, When пользователь нажимает «Скрыть», Then панель полностью исчезает из рабочей области, запись и ASR продолжаются.
Given API недоступен, When приходит новый звук, Then транскрипция и запись работают локально, а панель честно показывает, что аналитика не обновлена.
```

Зависимости: T4–T9. Риск: R10, R4.

### US-08. Контроль внешнего API и стоимости

Как владелец данных, я хочу разрешать конкретный провайдер и понимать расход токенов, чтобы не передавать персональные данные без оснований и контролировать затраты.

Критерии приёмки:

```gherkin
Given внешняя передача не согласована, When приложение готовит LLM-запрос, Then сетевой вызов запрещён и текст интервью остаётся локальным.
Given разрешённый провайдер и действующий API-ключ настроены, When отправляется минимизированный запрос, Then сохраняются модель, версия, число токенов, оценка стоимости и хеш фактического входа без логирования ключа.
Given провайдер вернул 429 или исчерпана квота, When приложение повторяет обращение, Then действует ограниченный backoff и лимит запросов, после чего включается локальный fallback без потери записи.
```

Зависимости: H4, Privacy Gateway, Keychain. Риск: R7, R8, R10.

### US-09. Архив, воспроизведение и экспорт

Как рекрутер, я хочу хранить транскрипт, аудио, правки, заключение и журнал проверки в одном месте, чтобы перепроверять источники и передавать результат руководителю.

Критерии приёмки:

```gherkin
Given интервью завершено, When рекрутер открывает архив, Then доступны запись, транскрипт, история исправлений, таблица и статусы подтверждения.
Given пользователь нажимает на тайм-код вывода, When исходное аудио сохранено, Then плеер переходит к указанному времени и показывает соответствующую реплику.
Given пользователь выбирает экспорт, When он сохраняет результаты, Then формируются корректные TXT, Markdown, JSON, SRT, VTT и воспроизводимый аудиофайл при наличии записи.
```

Зависимости: T5, T12, журнал. Риск: R9.

### US-10. Режим поддержки соискателя

Как соискатель, я хочу заранее описать пожелания к работодателю свободным текстом и получить разбор собственных ответов, чтобы понять, что уточнить и как улучшить самопрезентацию.

Критерии приёмки:

```gherkin
Given выбран режим «Соискатель», When пользователь вводит пожелания о графике, зарплате и обучении, Then система предлагает редактируемые структурированные критерии, сохраняя исходный текст.
Given на интервью условия обучения не обсуждались, When формируется итог, Then система пишет «не выяснено», а не «у работодателя нет обучения».
Given вопрос не имеет объективно проверяемого правильного ответа, When ИИ анализирует ответ, Then он оценивает релевантность и аргументацию с ограничениями, не придумывая процент вероятности оффера.
```

Зависимости: режим собеседования, LLM, H4 для внешнего API. Риск: R13, R4.

### US-11. Универсальный режим совещаний и задач

Как участник совещания, я хочу получать стенограмму, тезисы, решения и назначенные задачи, чтобы не потерять договорённости независимо от сервиса ВКС.

Критерии приёмки:

```gherkin
Given выбран режим «Совещание», When участники обсуждают решение и назначают исполнителя, Then система создаёт черновик решения или задачи со ссылкой на исходную реплику.
Given участники лишь рассматривают вариант, When модель извлекает пункт, Then он отмечается «на обсуждении», а не «решено».
Given задача не имеет названного ответственного или срока, When отображается таблица, Then поля показывают «не назначен» / «срок не определён» без выдуманных значений.
```

Зависимости: T3–T9, H2 для подтверждения протокола. Риск: R4.

### US-12. Импорт и локальная транскрибация аудиофайла

Как пользователь, я хочу загружать аудиозапись и транскрибировать её на Mac, чтобы получать стенограмму без отправки аудио в облако.

Критерии приёмки:

```gherkin
Given выбран поддерживаемый аудиофайл, When пользователь запускает обработку, Then локальная модель создаёт сегменты с тайм-кодами и отображает прогресс.
Given файл повреждён или не декодируется, When импорт завершается ошибкой, Then приложение показывает понятную причину, не создаёт фиктивный транскрипт и не удаляет исходный файл.
Given обработка завершена, When пользователь запускает повторную транскрибацию, Then исходная версия и ручные исправления доступны для восстановления.
```

Зависимости: локальный ASR, хранилище. Риск: R5, R9.

## Use Cases

### UC-01. Провести интервью с доказательным заключением

| Поле | Значение |
|---|---|
| Актёры | Рекрутер, кандидат, нанимающий руководитель; приложение и внешний LLM как технические исполнители |
| Предусловия | Утверждённая вакансия, доступные аудиоисточники, локальная ASR-модель; получены необходимые разрешения на выбранную обработку |
| Триггер | Рекрутер нажимает «Начать интервью» |

Основной сценарий:

1. Рекрутер вставляет вакансию и утверждает извлечённые критерии (US-01).
2. Указывает участников и при согласии привязывает голоса (US-04).
3. Система проверяет H0 — законность и разрешения записи (US-02).
4. После начала записи локальный захват и Whisper создают синхронное аудио и транскрипт (US-02/03).
5. Рекрутер при необходимости корректирует говорящих и спорные фрагменты H1 (US-04).
6. Policy Engine проверяет H4 и минимизирует данные при разрешённой передаче (US-08).
7. Разрешённая LLM создаёт структурированную таблицу по вакансии и доказательства (US-05/07).
8. Система проверяет ссылки и показывает «черновик» или «не выяснено» (US-05).
9. Рекрутер проверяет и редактирует выводы H2, сохраняет обоснования (US-06).
10. Руководитель независимо принимает решение о следующем шаге H3 (US-06).
11. Система сохраняет журнал, запись и заключение; пользователь экспортирует результат (US-09).

Альтернативные сценарии:

| # | Условие | Реакция |
|---|---|---|
| 3a | Нет необходимых разрешений на запись | H0: ручной режим без записи; кандидат не наказывается |
| 5a | Диаризация неоднозначна | H1: метка «неизвестный», ручная корректировка, зависимые выводы на перепроверку |
| 6a | Запрещён внешний API | H4: локальная стенограмма, ручное заключение; нет фиктивной LLM-сводки |
| 8a | Вывод не имеет подтверждающих сегментов | Валидатор маркирует «не подтверждено», H2 отклоняет либо перепроверяет |
| 9a | HR не согласен с ИИ | H2: правка/отклонение с причиной, история версии сохраняется |
| 10a | Руководитель не ответил в SLA | H3: статус «ожидает решения», эскалация человеку, автоматический отказ запрещён |

Исключения:

| # | Ошибка | Реакция |
|---|---|---|
| 4b | Пропал микрофон/источник | Сохранить имеющиеся данные, предупредить о неполной записи |
| 6b | Нет сети, API 401/429/500 | Ограниченные retries; локальный fallback; ключи и ПДн не логировать |
| 8b | Невалидный JSON или несуществующие source IDs | Не утверждать вывод, сохранить техническую причину, предложить повторную попытку |
| 11b | Недостаточно места | Остановить захват безопасно и сохранить уже записанную часть |

**Постусловия:** имеется либо проверенное заключение и зафиксированное действие руководителя, либо явный статус «не завершено / ожидает решения». Автоматических отказов нет.

### UC-02. Работать без внешней LLM

| Поле | Значение |
|---|---|
| Актёры | Рекрутер, приложение |
| Предусловия | Разрешён локальный захват, ASR-модель установлена; внешняя отправка выключена |
| Триггер | Пользователь выбирает «Только локально» или запрет H4 |

Основной сценарий:

1. Пользователь начинает разрешённую запись.
2. Приложение захватывает аудио и транскрибирует локально.
3. Показывает стенограмму, говорящих и тайм-коды.
4. Отключает внешние вызовы и помечает LLM-аналитику «не выполнялась».
5. Рекрутер вручную составляет или корректирует заключение.
6. Руководитель принимает кадровое решение независимо.

Альтернативные сценарии:

| # | Условие | Реакция |
|---|---|---|
| 1a | Не разрешена и локальная запись | Ручные заметки без аудио, проверка H0 |
| 4a | Появилось разрешение API позже | H4 требует самостоятельного подтверждения перед новым вызовом; старая запись не выгружается автоматически |

Исключения:

| # | Ошибка | Реакция |
|---|---|---|
| 2b | Нет локальной модели | Показать требование установки; не выдавать имитацию транскрипта |

**Постусловия:** данные остаются локально, есть ручной либо проверенный документ; запись/ASR не зависит от сети.

### UC-03. Разобрать собеседование в режиме соискателя

| Поле | Значение |
|---|---|
| Актёры | Соискатель, приложение |
| Предусловия | Соискатель владеет собственным профилем и имеет необходимые разрешения на обработку разговора |
| Триггер | Пользователь открывает режим «Соискатель» |

Основной сценарий:

1. Пользователь свободным текстом задаёт предпочтения и личные инструкции.
2. Система предлагает их структурированную интерпретацию; пользователь подтверждает.
3. После разрешённой записи/загрузки аудио выполняется локальная стенограмма.
4. Система выделяет вопросы и ответы; проверяет только фактически проверяемые технические утверждения.
5. Разрешённая LLM сопоставляет обсуждённые условия с предпочтениями и формирует черновик советов.
6. Пользователь проверяет выводы, отмечает неточности и сохраняет личную сводку.

Альтернативные сценарии:

| # | Условие | Реакция |
|---|---|---|
| 4a | Вопрос субъективный | Показывать комментарий о релевантности, а не «неправильный ответ» |
| 5a | Условие работы не обсуждалось | Статус «не выяснено» и вопрос для работодателя |
| 5b | Нет разрешения на внешний анализ | Локальная стенограмма и ручной разбор без API |

Исключения:

| # | Ошибка | Реакция |
|---|---|---|
| 3b | Нет записи либо файл не декодируется | Показать ошибку, не фабриковать вопросы и ответы |

**Постусловия:** персональная сводка без неподтверждённого процента вероятности оффера и без передачи результата работодателю.

### UC-04. Транскрибировать загруженный аудиофайл

| Поле | Значение |
|---|---|
| Актёры | Пользователь, приложение |
| Предусловия | Локальная ASR-модель установлена, файл получен правомерно |
| Триггер | Пользователь выбирает «Транскрибировать файл» |

Основной сценарий:

1. Пользователь выбирает WAV/MP3/M4A либо другой подтверждённый декодером формат.
2. Приложение проверяет доступность файла и формат.
3. Выполняет локальную обработку частями и показывает прогресс.
4. Сохраняет транскрипт с тайм-кодами; имена говорящих уточняются пользователем.
5. Пользователь редактирует результат и экспортирует TXT/MD/JSON/SRT/VTT.

Альтернативные сценарии:

| # | Условие | Реакция |
|---|---|---|
| 4a | Диаризация не определила участников | Отображать нейтральные speaker IDs и разрешить назначение вручную |
| 5a | Нужно более точное ASR | Перезапуск с другой локальной моделью, сохранение предыдущей версии |

Исключения:

| # | Ошибка | Реакция |
|---|---|---|
| 2b | Повреждён файл или неподдерживаемый кодек | Понятное уведомление; оригинал остаётся неизменным |
| 3b | Прервалась обработка | Безопасная отмена, сохранение завершённых сегментов, без имитации готового результата |

**Постусловия:** локальная стенограмма либо зарегистрированная ошибка; аудио не передано внешнему ASR.

## Нефункциональные требования

| Категория | Требование | Проверяемость |
|---|---|---|
| Производительность | Для согласованного сбалансированного ASR-профиля стремиться к p95 задержки появления устойчивого сегмента не более 12 с на тестовом Mac M1; UI не блокируется | Измерить задержки на часовой тестовой записи и живом потоке, привести p50/p95 и конфигурацию; при превышении — отклонение критерия |
| Потоковая аналитика | При доступном разрешённом API и квоте обновлять аналитический черновик не реже одного раза в 120 с при наличии новых устойчивых сегментов | Логировать время подтверждения сегментов и публикации сводки, измерить p95; лимит провайдера фиксировать отдельно |
| Надёжность | Ошибка API или закрытие аналитической панели не останавливают захват/локальную запись; подтверждённые сегменты сохраняются транзакционно | E2E-тесты отключения сети, HTTP 429/500, скрытия панели, аварийной остановки; проверка восстановления |
| Качество распознавания | Отдельно оценивать WER/CER и точность словаря терминов на русском и код-свитчинге; не обещать 100% точности | Сравнение с размеченным аудио; публикация реальных WER/CER и размера выборки |
| Качество аналитики | Не менее 95% значимых фактов из эталонной разметки и 95% фактических выводов с корректными ссылками; ложный факт не может быть утверждён без HR | Независимая двойная разметка, оценка recall и корректности ссылок, аудит H2 |
| Безопасность | Ключи API в Keychain; запрет неавторизованных действий; принцип минимальных прав | Статический поиск секретов, интеграционные тесты доступа, тесты логирования |
| Приватность | Аудио и голосовые профили не отправляются в облако; внешний текстовый API выключен по умолчанию; без H0/H4 запрос не уходит | Перехват сетевых запросов в тестовом окружении, проверка consent_log и правил политики |
| Срок хранения | Предлагаемая политика пилота: аудио не более 30 дней, протокол/аудит — до 90 дней, **если согласовано с ИБ и применимыми правилами**; удаление данных по роли | Тесты истечения TTL и ручного удаления; отдельно согласовать срок до реального пилота |
| Объяснимость | Любой фактический вывод, передаваемый HR, имеет существующие source_segment_id и тайм-код либо статус «не подтверждено» | Валидация схемы и случайная ручная проверка по записи |
| Аудит | Для каждого принятия/отклонения вывода есть actor, timestamp, version, input_hash, действия H2/H3; обычные логи без текста/ключей | Проверка журналов, хеша канонического входа и прав просмотра |
| Локализация | Русский интерфейс; поддержка русского ASR и английских терминов, пользовательский словарь | UI-тесты и размеченные записи с RAG/LLM/СУДИР/TrueConf |
| Сопровождаемость | Модули захвата, ASR, LLM и хранилища разделены интерфейсами; закреплены версии зависимостей | Архитектурное ревью и тест замены API-провайдера без изменения HR-логики |
| Стоимость | Система считает входные/выходные токены, тариф/модель и пользовательский лимит; при превышении не инициирует платный вызов | Синтетические данные usage и тесты блокировки следующего запроса |
| Управляемость окна | Боковую аналитическую панель можно скрыть/показать без остановки записи | UI/E2E-тест с непрерывной аудиозаписью |
| Совместимость | Первая сборка — macOS/Apple Silicon; нет требования к Windows-релизу в пилоте | Сборка и E2E на Mac M1; архитектурные границы проверяются код-ревью |

## Ограничения и допущения

| Ограничение | Источник |
|---|---|
| В рамках текущего MVP приложение разрабатывается для Mac; Windows — будущая платформа | Наши технически и временные ограниченния |
| Аудио транскрибируется локально; вызов внешней LLM возможен только с разрешённым текстом | Концепция и архитектура TO-BE |
| Кадровые решения принимает уполномоченный человек, не алгоритм | Требования к Human-in-the-Loop в методике: https://github.com/hrtech2026/hrtech-practice/blob/main/docs/methodology.md |
| Ограничения API по тарифам/запросам меняются, бесплатность токенов не гарантирует доступность | https://api-docs.deepseek.com/quick_start/pricing/ и https://openrouter.ai/collections/free-models |
| Требуются разрешения macOS на захват доступного аудио; защищённые и недоступные источники не гарантированы | https://developer.apple.com/documentation/screencapturekit |
| Правомерность записи и передачи содержимого интервью должна быть подтверждена применимыми правилами организации и согласиями | Условие запуска пилота; согласование юриста/ИБ для корп. использования |

**Допущения:**

| Допущение | Кто подтвердит | Что меняется, если неверно |
|---|---|---|
| Рекрутеры готовы использовать запись и проверять выводы | HR-заказчик и пилотные рекрутеры | Вернуться к ручной схеме; изменить интерфейс |
| ASR справится с русским и терминологией достаточно для подтверждаемых фактов | Технический эксперт, эксперт разметки | Изменить модель, словарь, процедуру проверки |
| Внешний провайдер разрешён для нужной категории данных | ИБ, юрист/ответственный за ПДн | Полностью локальный вариант либо отказ от LLM в пилоте |
| Нагрузка Mac M1 приемлема для потока | Команда по результатам тестирования | Облегчить ASR-профиль или использовать обработку после интервью |
| Экономия HR-времени перевешивает проверку и поддержку | Бизнес-заказчик после A/B-анализа | Не масштабировать, пересмотреть дизайн |
| Подбор критериев вакансии достаточно определён | Нанимающий руководитель | Добавить обязательное утверждение критериев и уточняющее интервью |

## Definition of Ready

- [ ] Пользователь и его роль определены.
- [ ] Ценность истории описана в одну фразу.
- [ ] Сценарии Given/When/Then согласованы.
